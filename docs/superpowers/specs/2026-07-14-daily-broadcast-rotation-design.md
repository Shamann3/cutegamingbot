# Ежедневная ротация рассылок — дизайн

## Задача

Раз в день (по умолчанию 12:00 **UTC** — см. предупреждение ниже) слать всем
игрокам одно из 8 согласованных сообщений по кругу, зовущих зайти в игру,
с кнопкой-вебапп под сообщением. Часть сообщений условна (по балансу), чтобы
не утверждать неправду о состоянии игрока.

## Решение

Никакой новой инфраструктуры — расширение уже существующей рассылки
(`server/admin_broadcast.py`) и уже тикающего раз в 30с планировщика
(`server/event_scheduler.py`), по образцу того, как там уже реализованы
повторяющиеся квесты (`_advance_recurring_quests`).

### Хранение состояния — `system_settings` (singleton-строка id=1)
Новые колонки: `daily_broadcast_enabled`, `daily_broadcast_hour`,
`daily_broadcast_minute`, `daily_broadcast_rotation_index`,
`daily_broadcast_next_fire_at`.

### Тексты — `DAILY_ROTATION_TEMPLATES` (`server/admin_broadcast.py`)
8 сообщений, зафиксированных с владельцем проекта. У двух — условие
`min_balance` (строго больше 100 / строго больше 50): при срабатывании этого
слота аудитория рассылки фильтруется через уже существующий
`filter_json.minBalance` (переиспользован без изменений).

### Срабатывание — `server/event_scheduler.py::_fire_daily_rotation_broadcast`
Вызывается из `_tick()` каждые 30с (как всё остальное в этом модуле).
Атомарный claim через `UPDATE system_settings ... WHERE daily_broadcast_next_fire_at
= $1` — тот же паттерн защиты от гонок, что у `_advance_recurring_quests`.
При первом тике после деплоя/включения только выставляет расписание, не
стреляет сразу. Если у выбранного по расписанию шаблона в моменте 0
получателей (условие никому не подходит) — не падает, просто логирует и ждёт
следующего дня.

### CTA-кнопка — `server/telegram_notify.py`
Добавлен `reply_markup` с `web_app`-кнопкой (открывает вебапп прямо в
Telegram, не во внешнем браузере — работает только в личке с ботом, что и
есть кейс рассылок). Поля `cta_text`/`cta_url` добавлены в `broadcast_runs`,
общие для ЛЮБОЙ рассылки, не только ежедневной ротации.

### Управление — `GET/POST /admin/api/broadcast/daily-rotation`
Включить/выключить, поменять час/минуту (UTC). Полноценного UI-тумблера в
админке пока нет — по запросу можно добавить в `BroadcastSection.jsx`.

## ⚠️ Важно: время — в UTC, не в московском

`daily_broadcast_hour=12` по умолчанию означает **12:00 UTC = 15:00 МСК**, не
12:00 по Москве. Если нужно ровно полдень по Москве — выставить
`hour=9` через `POST /admin/api/broadcast/daily-rotation`.

## Вне рамок
- UI-тумблер в `BroadcastSection.jsx` (расписание сейчас управляется через API).
- Сообщение #7 ("Твоя позиция в топе изменилась") утверждает то, что не
  всегда буквально верно для каждого получателя — оставлено как согласовано
  с владельцем проекта, без условной проверки.
