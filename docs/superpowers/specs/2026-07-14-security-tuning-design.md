# Security tab — Фаза 3: точечные улучшения

## Проблема

Детекция угроз (`server/security_watch.py`, `server/auth.py`, `server/rate_limit.py`)
уже работает и пишет реальные алерты. Но:

1. Реальная блокировка IP (`ip_bans` + `IpBanMiddleware`) существует, но ничего
   и никогда не добавляет туда IP автоматически — сканер/бот может триггерить
   алерты бесконечно, ничего не блокирует его до ручного бана админом.
2. Неудачные попытки входа в саму админку (неверный ключ/2FA) нигде не логируются
   — только финальный случай "нет такого аккаунта".
3. Security-вкладка — плоский хронологический список; при фоновом сканировании
   интернета (постоянный шум для любого сервера) это нечитаемо без группировки.

## Решение

### 1. Автобан по порогу (`server/error_reporter.py`)
В `report_error()` — если код относится к security (`is_security_code`) и есть
`client_ip`, считаем попадания в скользящем окне 5 минут. При 20+ попаданий с
одной IP — автоматически вызываем существующий `ip_ban.add_ip_ban()` (тот же
путь, что и ручной бан из панели), бан на 1 час, `banned_by=0` (маркер
"система", отличим от банов админов). Порог/окно/срок — константы в начале
файла, легко подкрутить.

Примечание: `/admin/api/auth/*` исключён из проверки `IpBanMiddleware`
намеренно ("Never block admin auth", `server/app.py:80`), чтобы админ не мог
случайно заблокировать сам себе вход. Значит автобан не остановит перебор
именно логина в админку (для этого уже есть отдельный
`admin_auth_rate_limit.py`, 20 попыток/300с) — но остановит сканеры/SQLi-пробы/
rate-abuse на всех остальных путях.

### 2. Лог неудачного входа в админку (`server/admin_routes.py::admin_login`)
Новый код `ERR_SEC_ADMIN_LOGIN_FAIL` (`server/error_codes.py`). Алерт при
неверном ключе входа и при неверном коде 2FA — раньше это нигде не появлялось.

### 3. Топ IP за сегодня (Security-вкладка)
`get_logs_overview()` (`server/admin_logs.py`) — новое поле `topSecurityIps`:
`GROUP BY client_ip` по `system_logs` за сегодня, топ-15 по количеству.
`LogsSection.jsx` — карточка над списком (видна только на вкладке Security),
показывает IP, число событий, время последнего.

## Вне рамок

- TOTP не трогаем — уже обязателен для всех админов.
- `admin_auth_rate_limit.py` не трогаем — уже работает (20/300с на IP).
- Новое устройство/IP при успешном входе (anomaly-алерт на сам факт логина) —
  не делаем, это отдельная фича, а не тюнинг существующего.

## Проверка

- Симуляция: 20+ запросов с одного IP на несуществующий путь (`/wp-admin`
  и т.п.) за 5 минут → IP появляется в `ip_bans` с `reason` начинающимся на
  "Автобан", дальнейшие запросы с этой IP получают 403 `ERR_IP_BANNED`
  (кроме `/admin/api/auth/*`).
- Неверный ключ/2FA при входе в админку → новая строка в Security с кодом
  `ERR_SEC_ADMIN_LOGIN_FAIL`.
- Вкладка Security показывает карточку "Топ IP за сегодня" при наличии данных.
