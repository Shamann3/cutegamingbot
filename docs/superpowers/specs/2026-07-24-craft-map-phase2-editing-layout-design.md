# Craft Map — Этап 2: редактирование крафтов, доступ и вёрстка

**Дата:** 2026-07-24
**Статус:** дизайн утверждён, готов к плану реализации
**Ветка:** `claude/craft-chain-visual-editor-6a5422`
**Предыдущий этап:** [2026-07-23-craft-map-visual-editor-design.md](2026-07-23-craft-map-visual-editor-design.md) (read-only карта)

## Контекст

Read-only карта крафтов (Этап 1) выкачена и работает: показывает предметы `dex`
карточками, рецепты `craft_recipes` — связями, с поиском, фильтрами, подсветкой
цепочки, панелью свойств, контекстным меню, статистикой и детектором ошибок
(на живых данных он уже нашёл реальный цикл и недостижимые предметы).

Этот этап добавляет: создание/удаление крафтов прямо с карты, ограничение
доступа к карте (только владелец, только ПК), и точечную перевёрстку админки
(контент на всю ширину, карта на весь экран).

## Ключевые факты кодовой базы (проверено)

1. **Таблицы крафта.** `craft_recipes` — источник правды для вебапп-игры и
   админки; именно её показывает карта (`get_craft_map` → `all_craft_recipes`
   → `_fetch_craft` из `craft_recipes`). Старая таблица `craft` (эмодзи-пары,
   `craftchance`) — легаси; `main.py` её не читает (по грепу), при старте есть
   одноразовая миграция `craft` → `craft_recipes`. **Add/delete пишем в
   `craft_recipes`.**
2. **Готовые эндпоинты.** `create_craft_recipe` / `delete_craft_recipe`
   (`server/admin_content.py`), маршруты `POST /content/craft`,
   `DELETE /content/craft/{id}` под `require_admin_permission("manage_content")`,
   и клиентские `createContentCraft` / `deleteContentCraft`
   (`admin/src/lib/adminClient.js`) — **переиспользуем, новый бэкенд не нужен.**
   `create_craft_recipe` проверяет уникальность `key` и пары ингредиентов;
   ошибки прилетают как `ValueError` → HTTP 400.
3. **Роль владельца** — `role === 'owner'` (в `PanelShell` есть state `role`,
   заголовок «👑 Владелец» в `PanelSidebar`).
4. **`ContentSection()` сейчас без пропсов** — `role` нужно прокинуть из
   `PanelShell`.
5. **Детекция устройства** — `admin/src/lib/perfMode.js`
   (`/iPhone|iPad|Android|Mobile/` + `innerWidth <= 1024` + matchMedia).
6. **Вкладки карты** живут в `ContentSection.jsx` (`TABS`), карта — компонент
   `CraftMapView`. Рецепты на карте — это **рёбра**, предметы — узлы.

## Принятые решения (развилки)

| Развилка | Решение |
|---|---|
| Добавление крафта | Кнопка «＋ Новый крафт» → мини-панель (форма), не drag-to-connect. |
| Таблица | `craft_recipes` (переиспускаем готовые эндпоинты). |
| Вёрстка | Точечно: контент на всю ширину, карта на весь экран; прочие разделы не трогаем. |
| Доступ к карте | Только `role === 'owner'` **и** десктоп; на моб/у не-владельца вкладки нет. |

## A. Доступ к карте: только владелец + только ПК

- Вкладка «🗺 Карта» добавляется в `TABS` **условно**: только если
  `role === 'owner'` И `isDesktop`.
- `isDesktop` — живой media-query хук (`admin/src/lib/useIsDesktop.js`):
  `window.matchMedia('(min-width: 1024px) and (pointer: fine)')` с подпиской на
  изменения (реагирует на ресайз/поворот). Тач-телефоны и узкие вьюпорты → не
  десктоп.
- `role` прокидывается пропсом `PanelShell` → `ContentSection`.
- Guard: если активная вкладка `map`, но условие доступа стало ложным (ресайз в
  узкое окно, не-владелец) — авто-переключение на `items`.

## B. Добавление и удаление крафтов

Пишем только в `craft_recipes` через существующие эндпоинты. После любой правки —
рефетч `fetchCraftMap()`, чтобы узлы/рёбра/статистика/ошибки пересчитались.

### Добавление
- Кнопка «＋ Новый крафт» в тулбаре карты (видна только владельцу на ПК, как и
  сама карта).
- Открывает мини-панель поверх карты (`AddCraftPanel`): выбор результата +
  ингредиента A + ингредиента B (поиск по dex — переиспользуем
  `DexItemSearchPicker`), поля «шанс успеха %» и «кол-во на выходе».
- Валидация на клиенте: 3 предмета выбраны, A ≠ B (как в существующем мастере).
- `key` генерируется автоматически: `map_<resultId>_<ingA>_<ingB>`, приведённый
  к `^[a-z][a-z0-9_]{1,48}$` (совпадает с валидатором бэкенда); при коллизии
  ключа/пары бэкенд вернёт 400 — показываем текст ошибки тостом
  (`notifyAdmin(..., {error:true})`), панель не закрываем.
- Успех → тост, закрыть панель, `fetchCraftMap()` рефетч, авто-фокус/подсветка
  нового результата (по возможности).

### Удаление
- В `PropertiesPanel`, в списке «Рецепты создания» у каждого рецепта — кнопка 🗑.
- Клик → подтверждение (существующий `AdminActionModal` или инлайн-подтверждение)
  → `deleteContentCraft(recipeId)` → тост → `fetchCraftMap()` рефетч.
- Удаление привязано к конкретному рецепту (рёбра), а не к карточке-предмету.

### Согласованность
- Действия add/delete видны только владельцу на ПК (та же гейт-логика, что и
  вкладка). На всякий случай кнопки не рендерятся, если `!canEdit`.

## C. Вёрстка: контент на всю ширину + карта на весь экран

- Найти CSS, центрирующий/ограничивающий контентную область
  (`.panel-layout` / `.panel-layout-content` в `admin/src/index.css`), и для
  раздела «Контент» сделать её на всю ширину (убрать `max-width`/центрирование).
- Вкладка «Карта»: рабочее пространство `.craftmap-wrap` растягивается на всю
  доступную высоту области контента (сейчас фикс. `72vh`) и ширину — «на весь
  экран» в пределах контента; тулбар/вкладки/статистика остаются сверху.
- Прочие разделы (Дашборд, Игроки, …) не трогаем — изменения скоупим классами
  раздела «Контент»/карты, чтобы не ловить регрессии в остальных секциях.
- Светлая/тёмная тема сохраняется.

## D. Стабильность, полировка, единое визуальное состояние

- **Единая производная визуального состояния карты.** Сейчас поиск (Task 9),
  подсветка цепочки (Task 10) и фокус ошибок (Task 13) пишут `node.data.dimmed/
  highlighted/errored` тремя разными эффектами без общего сброса — после кликов
  бывает «залипание». Заменяем на один `useMemo`, который из входов
  `{selectedId, chain, matchedIds, visibleIds, errorFocusSet, query}` выводит
  визуальные пропсы узлов/рёбер и применяется одним `setNodes`/`setEdges`.
  Это заодно чинит отложенные баги Этапа 1 (поиск не восстанавливается после
  снятия цепочки; «Найдено: 0» без затемнения; стиль отключённых рёбер).
- Аккуратные состояния загрузки/ошибок/подтверждений в панелях add/delete под
  общий стиль админки.

## Тестирование и верификация

- **Юнит-тесты (vitest):** если появляется чистая логика (напр. генерация
  `key`, вывод визуального состояния — вынести в чистую функцию и покрыть).
  Существующие graph-тесты должны остаться зелёными.
- **Сборка:** `npm --prefix admin run build` без предупреждений/ошибок.
- **Живой прогон (я сам, в браузере на собранной админке):**
  - вкладка «Карта» видна владельцу на ПК; исчезает при сужении окна и (симуляция)
    у не-владельца; авто-фолбэк работает;
  - «＋ Новый крафт»: создание рецепта → появляется на карте, статистика растёт;
    ошибка дубликата → тост, панель открыта;
  - удаление рецепта из панели свойств → исчезает с карты;
  - контент на всю ширину, карта на весь экран; тёмная/светлая тема;
  - подсветки (поиск/цепочка/ошибки) не залипают после переключений.

## Границы этапа (не входит)

- Изменение модели крафта (N ингредиентов, количество на связях «×5») — требует
  ломающих изменений `craft_recipes` и игровой логики; отдельный этап.
- Drag-to-connect создание рецептов линиями (выбрана форма-панель).
- Редактирование самих предметов dex, история/undo, импорт-экспорт, массовые
  действия — вне этого этапа.
- Синхронизация в легаси-таблицу `craft` — не требуется (`craft_recipes` —
  источник правды).
