# Craft Map — визуальный редактор цепочек крафта (Этап 1: read-only карта)

**Дата:** 2026-07-23
**Статус:** дизайн утверждён, готов к плану реализации
**Ветка:** `claude/craft-chain-visual-editor-6a5422`

## Контекст и цель

Сейчас крафты в админ-панели создаются через пошаговый мастер
(`admin/src/components/CraftRecipeWizard.jsx`) внутри
`admin/src/pages/sections/ContentSection.jsx`. При росте числа предметов
взаимосвязи между рецептами трудно охватить: нельзя быстро увидеть полную
цепочку, тяжело находить ошибки и анализировать зависимости.

Долгосрочная цель — полноценный визуальный node-редактор крафтов
(в духе Blender / Unreal / Unity Shader Graph), который заменит текущую
систему. Эта работа большая и разбита на этапы. **Данная спецификация
покрывает только Этап 1: интерактивная read-only карта.**

## Ключевые ограничения (реальность проекта)

Изучение кодовой базы зафиксировало факты, определяющие границы этапа:

1. **Модель рецепта жёстко ограничена.** Таблица `craft_recipes`
   (`server/schema.sql:156`) — ровно **2 ингредиента** (`ingredient_a_id`,
   `ingredient_b_id`), количество каждого всегда **1**; на выходе один
   предмет `result_item_id` в количестве `result_qty`. В игре рецепт
   исполняется поиском по паре ингредиентов
   (`find_recipe_by_ingredient_pair`), т.е. пара должна быть уникальной.
   → «Железо ×5», `×N` ингредиентов и сходящиеся связи с количествами
   требуют ломающего изменения БД и игровой логики. **Вне этапа 1.**

2. **Предметы (`dex`)** имеют поля: `id` (int), `name`, `name1`, `emoji`,
   `price`, `dis`, `remains`, `sorting`, `bio`, `use`, `bonus`, `craft`
   (`server/dex_catalog.py:45`). **Нет** полей изображения, категории,
   редкости, уровня, координат, истории изменений.

3. Бэкенд — FastAPI, маршруты в `server/admin_routes.py` под
   `require_admin_permission("manage_content")`; бизнес-логика в
   `server/admin_content.py`. Схема БД применяется на старте из
   `server/schema.sql` (`server/db.py:236`) через `CREATE TABLE IF NOT
   EXISTS` / `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.

4. Админ-фронт — React 18 + Vite, стили `panel-*` в
   `admin/src/index.css`. Node-графовой библиотеки в проекте нет.

## Принятые решения (развилки)

| Развилка | Решение |
|---|---|
| Модель крафта | Этап 1 — **read-only**, поверх существующей 2×1 модели. Расширение модели откладывается. |
| Технология графа | **React Flow (`@xyflow/react` v12)** + `@dagrejs/dagre` для авто-раскладки. |
| Хранение позиций | **В БД, общие для всех админов** (новая таблица + эндпоинты). |
| Метаданные карточек | **Маппинг на существующие поля:** эмодзи = «изображение», `sorting` = категория/цепочка. Редкость/уровень/картинка не показываются (полей нет). |

## Границы Этапа 1

Новая вкладка **«Карта»** в `ContentSection` рядом с существующими
(Культуры / Дропы / Крафт). Старый `CraftRecipeWizard` **остаётся** —
карта на этом этапе только просмотр и анализ. Полная замена мастера —
на этапе визуального редактирования.

### Входит (всё read-only, кроме позиций узлов)

- Рабочее пространство React Flow: пан, зум колесом, мини-карта,
  авто-центрирование, быстрый переход к предмету.
- Карточки предметов: эмодзи-«изображение», название, ID, категория
  (`sorting`), цена, bio/use/bonus; hover-эффекты, скругления, тени,
  светлая/тёмная тема.
- Связи: рёбра ингредиент → результат из существующих рецептов; подпись
  рецепта; направление.
- Ручное перетаскивание карточек; координаты сохраняются в БД (общие).
- Авто-раскладка (dagre) по кнопке: базовые ресурсы слева → конечные
  справа, минимум пересечений.
- Поиск по названию / ID / категории / описанию: найденное
  подсвечивается, остальное затемняется.
- Фильтры по категории (`sorting`): скрытие категорий, переключение
  «цепочек».
- Подсветка цепочки: клик по предмету → путь вверх (из чего сделан) и
  вниз (где используется), остальное затемнено.
- Правая панель свойств: вся инфа о предмете, «рецепты создания»,
  «используется в», связанные предметы (read-only).
- Контекстное меню по ПКМ: показать цепочку, перейти к связанным,
  выделить связанные, копировать ID, копировать ссылку, фокус/центрировать.
- Проверка ошибок: циклы, битые ссылки, дубли рецептов, предметы без
  использования, недостижимые — список + подсветка на карте.
- Статистика сверху: предметов, рецептов, связей, базовых ресурсов,
  конечных, макс. и средняя глубина, число ошибок.

### Откладывается (следующие этапы)

- Создание/редактирование рецептов перетаскиванием линий, количество на
  связях, `×N` ингредиентов (требует расширения модели БД + игры).
- Редактирование/дублирование/удаление предметов из карты.
- История изменений, кто менял, откат версий, undo/redo.
- Импорт/экспорт JSON/PNG/SVG/PDF, массовые действия, полный набор
  горячих клавиш.

## Архитектура фронтенда

Следуем существующим паттернам админки. Модули изолированы по одной
ответственности (не один большой файл):

```
admin/src/components/craftmap/
  CraftMapView.jsx        — корень: загрузка данных, React Flow, оркестрация панелей
  useCraftMapState.js     — хук состояния: выделение, подсветка, поиск, фильтры
  graph/
    buildGraph.js         — чистая ф-ция: dex + recipes → nodes[] + edges[] + индексы
    layout.js             — dagre авто-раскладка → координаты
    analysis.js           — чистые ф-ции: обход цепочки, детектор ошибок, статистика
  nodes/ItemNode.jsx      — карточка (кастомный React Flow node)
  panels/
    StatsBar.jsx          — статистика сверху
    PropertiesPanel.jsx   — правая панель свойств
    SearchBar.jsx         — поиск
    FilterPanel.jsx       — фильтры по категориям
    ErrorsPanel.jsx       — список ошибок
    ContextMenu.jsx       — меню по ПКМ
```

Новые зависимости в `admin/package.json`: `@xyflow/react`, `@dagrejs/dagre`.
Стили карты — в `admin/src/index.css` (класс-неймспейс `craftmap-*`),
с поддержкой светлой/тёмной темы через существующие механизмы панели.

### Поток данных

1. Открытие вкладки → один запрос `GET /content/craft-map` →
   `{ items, recipes, positions }`.
2. `buildGraph()` строит узлы (предметы, участвующие в рецептах; тумблер
   «показать одиночные» добавляет dex-предметы вне рецептов) и рёбра
   (для рецепта `a + b → r`: `a→r` и `b→r` с метаданными рецепта).
3. Координаты: есть сохранённая → берём её; нет → dagre авто-раскладка.
4. Взаимодействия меняют локальное состояние подсветки/выделения;
   перетаскивание → сохранение в БД с debounce (батч).

### Обработка ошибок API

- Сбой загрузки карты → тост (`notifyAdmin`) + пустое состояние с кнопкой
  «Повторить».
- Сбой сохранения позиций неблокирующий: тост, локально позиция не
  теряется; повтор при следующем перетаскивании.

## Бэкенд

### Новая таблица (`server/schema.sql`, создаётся на старте)

```sql
CREATE TABLE IF NOT EXISTS craft_map_positions (
    item_id     TEXT PRIMARY KEY,
    x           DOUBLE PRECISION NOT NULL,
    y           DOUBLE PRECISION NOT NULL,
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_by  BIGINT
);
```

Одна общая раскладка для всех админов.

### Эндпоинты

Логика в `server/admin_content.py`, маршруты в `server/admin_routes.py`
под `require_admin_permission("manage_content")`:

| Метод | Путь | Назначение |
|---|---|---|
| `GET`  | `/content/craft-map` | `{ items:[...], recipes:[...], positions:{itemId:{x,y}} }` одним ответом |
| `POST` | `/content/craft-map/positions` | Батч-upsert `{ positions:[{itemId,x,y}] }` |

- `items` — все dex-предметы с полями, нужными карточке (id, name, name1,
  emoji, price, sorting, bio, use, bonus). Переиспользуем существующую
  выборку dex; при необходимости отдаём полный список без пагинации для
  карты.
- `recipes` — из `recipe_to_admin_dict` (уже отдаёт результат/ингредиенты
  с именами и эмодзи).
- `positions` — из `craft_map_positions`.

Клиент (`admin/src/lib/adminClient.js`): `fetchCraftMap()`,
`saveCraftMapPositions(list)`.

## Алгоритмы (чистые модули)

### `buildGraph.js`
- Узлы: предметы, участвующие в рецептах (+ тумблер «одиночные»).
- Рёбра: для рецепта `a + b → r` — `a→r` и `b→r`, тег = id/key рецепта,
  шанс, resultQty. Рёбра разных рецептов различаются по ключу
  `recipeId + slot`.
- Индексы: `producedBy` (item → рецепты-производители), `usedIn`
  (item → рецепты-потребители), прямая/обратная смежность.

### `layout.js`
- dagre, `rankdir` слева-направо; размер узла = размер карточки.
- Возвращает `{itemId: {x, y}}`. Применяется, когда нет сохранённой
  координаты (или по кнопке «авто-раскладка»).

### `analysis.js`
- **Подсветка цепочки:** вверх — обход рёбер назад от узла (до базовых
  ресурсов); вниз — вперёд (до конечных). Возвращает множества
  узлов/рёбер для подсветки.
- **Детектор ошибок** (каждая: `{type, severity, itemIds/edgeIds,
  message}`):
  - циклы — DFS по направленному графу;
  - битые ссылки — ингредиент/результат без записи в `dex`;
  - дубли рецептов — одинаковая неупорядоченная пара ингредиентов в ≥2
    включённых рецептах (коллизия исполнения);
  - предметы без использования — dex-предмет вне всех рецептов;
  - недостижимые — результат, чьи ингредиенты не сводятся к базовым
    (цикл/битая ссылка выше по цепочке).
- **Статистика:** предметов, рецептов, связей, базовых ресурсов (нет
  входящих), конечных (нет исходящих), макс. и средняя глубина
  (длиннейший путь по DAG; циклы исключаются/помечаются), число ошибок.

### Производительность
- `useMemo` на `buildGraph`/`analysis` по данным.
- Debounce сохранения позиций.
- React Flow `onlyRenderVisibleElements` для больших графов.
- Реальный масштаб (десятки–сотни предметов) — с большим запасом.

## Тестирование

- **Юнит-тесты (vitest, уже в проекте):**
  - `buildGraph` — деривация узлов/рёбер, индексы `producedBy`/`usedIn`;
  - `analysis` — обнаружение циклов, обход цепочки вверх/вниз, статистика,
    битые ссылки, дубль-пары, недостижимые;
  - обёртка `layout` — стабильность координат на простом графе.
  - Модули чистые, без React — импортируются и тестируются напрямую.
    Размещение файлов и подключение к `npm test` уточняется в плане
    реализации (в корне уже настроен vitest).
- **Ручная проверка (чек-лист):** пан/зум/мини-карта, поиск+затемнение,
  подсветка цепочки, фильтры, панель свойств, контекстное меню,
  перетаскивание+сохранение в БД, тёмная/светлая тема, пустое состояние,
  сбой API.

## Выкатка и риски

- Всё аддитивно: новая вкладка, старый мастер и игровая логика не
  затрагиваются. Бэкенд — новая таблица + 2 эндпоинта, без миграции
  данных. Низкий риск.
- Явно не входит в этап (управление ожиданиями): изменение количеств на
  связях, `×N` ингредиентов, редактирование предметов/рецептов с карты,
  история/откат/undo, импорт-экспорт файлов, массовые действия.
